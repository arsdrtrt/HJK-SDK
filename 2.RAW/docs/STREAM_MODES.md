# Режимы потока и доступность raw-данных

## Итоговая картина

| Путь | Доступен | Примечание |
|---|---|---|
| Вендорский SDK (`USBSDK_*`) | ✅ стабильно | основной путь |
| Прямой V4L2 (`/dev/video2`) | ⚠️ требует отвязки uvcvideo от SDK | тест в работе |
| Bulk-libusb без SDK | ⏳ требует реверса протокола | см. `1.SDK/docs/PROTOCOL.md` |

## Стабильность: конфликт с uvcvideo — РЕШЕНО

**Симптом:** после 1-3 успешных запусков `capture_raw` начинал падать
с `Segmentation fault`. В логе — `attempt to claim already-claimed interface 1`.

**Причина:** uvcvideo держит interface 1, SDK забирает его через
`libusb_detach_kernel_driver`, uvcvideo забирает обратно, USB-транзакция
рвётся в середине — падает транспортный поток `libhpr.so`.

**Решение:** udev-правило отвязывает uvcvideo от этой камеры при
подключении. См. `1.SDK/docs/LIFECYCLE.md`.

**Результат:** 5 из 5 запусков `capture_raw 20` → `exit 0`.

## Данные до NUC — недоступны

**Доказательство из захвата 500 кадров:**

| Кадр | max raw | Комментарий |
|---|---|---|
| 0 | 56317 (462 °C) | hot pixel виден до NUC |
| 2 | 13406 (34 °C) | после NUC — выброс подавлен |
| 208–499 | ~13400 | стабильно |

Если NUC не применяется, hot pixels присутствуют постоянно.
Они исчезают за 1-2 кадра — значит NUC выполняется в FPGA до USB.

**Вывод:** Y16 — **радиометрический поток после NUC/DPR**.
Данные до NUC физически не покидают чип.

## Периодические shutter-события

За 500 кадров (20 сек) — 3 shutter-события:
- кадр 128→129 (ΔT 2.1 °C)
- кадр 173→174 (ΔT 2.8 °C)  
- кадр 206→208 (ΔT −4.9 °C, двойной)

Период ~12 секунд. Это механический затвор для обновления NUC.
**Для измерений использовать только длинные стабильные сегменты**
(в нашем случае 208..499).
