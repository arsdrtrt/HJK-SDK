# 2.RAW — Получение сырых данных с минимальной обработкой

Цель: определить, какие данные сенсора доступны через SDK, и оценить,
можно ли получить поток до NUC/калибровки.

## Предварительный анализ

Архитектура микро-болометра (типичная):
  Сенсор (14-bit АЦП)
    → NUC (Non-Uniformity Correction, в FPGA)
    → DPR (Defective Pixel Replacement, в FPGA)
    → Упаковка в Y16 (16-бит контейнер)
    → USB (UVC isoch / bulk)

**Y16 — это НЕ сырой АЦП.** Это уже прошедший NUC сигнал, упакованный
в 16-бит. Для FLIR, HIKMICRO и других — это стандарт[reference:2].
Данные до NUC остаются внутри FPGA и не покидают чип[reference:3].

## Задачи

### 1. Захват Y16 и разбор заголовка

Что: снять поток через callback, сохранить в файл, найти заголовок.

Метод:
- `apps/capture_raw.cpp` — снимает N кадров, пишет в `raw16.bin`
- параллельно — `usbmon` + `Wireshark` для перехвата USB-пакетов
- сравнить: есть ли в USB-трафике заголовок до данных кадра

Результат: `docs/HEADER_ANALYSIS.md`

### 2. Что именно отдаёт SDK

Что: определить, какая обработка уже выполнена.

Метод:
- снять серию кадров при закрытом объективе (чёрное тело)
- рассчитать шум: `std` по пикселю во времени
- сравнить с паспортным NETD (если известен)

Результат: оценка "сколько шума съел NUC" в `docs/NETD_MRTD.md`

### 3. Типы потока

Что: перебрать все доступные UVC-форматы и вендорские команды.

Метод:
- `v4l2-ctl --list-formats-ext` — все пиксель-форматы
- `strings libHCUSBSDK.so | grep -i raw` — поиск режимов
- если есть команда переключения — попробовать через SDK

Результат: `docs/STREAM_MODES.md`

### 4. Данные до NUC

Что: оценить возможность доступа к АЦП.

Метод:
- реверс `libHCUSBSDK.so` — поиск команд, меняющих пайплайн
- проверка UVC XU (Extension Unit) — может быть команда "raw mode"
- если нет — зафиксировать как "недоступно"

Результат: раздел в `docs/HEADER_ANALYSIS.md`

### 5. NETD/MRTD по Y16

Что: измерить шумовые и контрастные характеристики по тому, что есть.

Метод (NETD):
- чёрное тело, 2 температуры (T1, T2), разница ΔT
- 100 кадров на каждой
- NETD = σ / (ΔV/ΔT) — где σ — временной шум, ΔV — отклик на ΔT

Метод (MRTD):
- мирра Фуко или 4-bar target
- визуальная оценка или MTF-анализ

Результат: `docs/NETD_MRTD.md` с явной оговоркой:
"Измерение по Y16 даёт **оптимистичную оценку**. Реальный NETD
сенсора выше, т.к. часть шума подавлена NUC/DPR."

## Инструменты

- `v4l2-ctl` — форматы и параметры UVC
- `usbmon` + `Wireshark` — перехват USB-трафика[reference:4]
- `IDA Pro` / `Ghidra` — реверс `libHCUSBSDK.so`
- `Python (numpy)` — анализ шума, расчёт NETD
